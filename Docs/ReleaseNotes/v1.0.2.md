# QuinSlate 1.0.2

> _Last updated: 2026-09-07_

Released from `v1.0.1..HEAD` (7 commits; the manifest bump to `1.0.2.0` is in the
working tree, not yet committed).

## User-facing

- **Live-preview markdown formatting** (`a67afab`). Headings, bold, italic,
  strikethrough, inline code and horizontal rules render while the markers stay in
  the buffer `.txt`, hidden by replace decorations and revealed again on whichever
  line the selection is on. Entirely page-side: three pure scanners
  (`build/src/blockFormat.js`, `codeSpans.js`, `inlineScan.js`), one view plugin
  (`markdownFormat.js`), and `editor.css`. No host or bridge changes, nothing
  written to the document, no keymap registered. Spec
  `Docs/Specs/23-MARKDOWN-FORMATTING.md`; the decision not to pull in a markdown
  parser is ADR `Docs/Decisions/05-MARKDOWN-IN-HOUSE-SCANNER.md`.
  - Emphasis is deliberately narrower than CommonMark: `*` only (never `_`, so
    `snake_case` survives), no whitespace inside a delimiter run, no word character
    outside one. That last rule is what keeps `2*3*4 =` arithmetic rather than
    italics, so the inline calculator still sees the line it expects.
  - `verticalMotion.js` wraps CM6's `moveVertically` behind Arrow and Page
    Up/Down. Without it the caret drifted by the marker width every time it crossed
    into a revealed line, because CM6 measures the destination while its markers are
    still hidden.
  - `links.js` gained two changes to coexist: it filters matches against claimed
    code spans, and its trailing-punctuation trim now drops `*` or `~` only when a
    run of that character is still open where the URL starts. `runDelimiters.js`
    holds the shared predicates; `links.js` and `inlineScan.js` must agree on them
    and neither may import the other. See `Docs/Specs/21-LINKS.md`.
- **The caret no longer blanks on clicks that never left the editor** (`0fbe427`).
  Dead panel chrome, the editor's own scrollbar, the left inset strip, a right press
  outside a selection, and the gaps beside a task checkbox all used to blur the
  content. Three independent layers were involved and each is handled where it
  occurs, documented in `Docs/Wiki/06-WEB-EDITOR-BUNDLE.md`:
  - XAML: `Components/EditorFocusGuard.cs` cancels the `LosingFocus` move for
    pointer input to a null target or to a ScrollViewer that is in the tab strip or
    detached. Scoping the guard to `BufferTabView` alone was not enough (20 of 48
    swept spots still lost focus).
  - Chromium: a native scrollbar press dispatches nothing to the page, so
    `build/src/scrollerFocus.js` returns focus to `.cm-content` after the fact.
  - Page: `editorSetup.js` suppresses Chromium's right-press default so the
    selection survives to the context menu.
  - The left inset moved from a WebView2 margin to `padding-left` on `.cm-line`
    (not `.cm-content`, which CM6's `rectanglesForRange` cannot see), making the
    strip part of the editor.
  - Task prefixes now render as a `.cm-task-marker` widget with a lead gap around
    the 15px `.cm-task-checkbox`; only the box toggles, so a click in either gap
    places the caret instead of checking the item.
    `Docs/Specs/19-CHECKABLE-TASKS.md` updated.
- **Minimize means minimize** (`b3ddce1`). The `WM_SYSCOMMAND`/`SC_MINIMIZE` and
  `WM_SIZE`/`SIZE_MINIMIZED` interceptions in `MainWindow.xaml.cs` are gone, along
  with the `isMinimizingToTaskbar` flag that 1.0.1 added to work around them, so a
  taskbar-button click and Win+D leave the panel as a taskbar button. Hide-to-tray
  is now reached only through the close button, the tray icon, and the hotkey.
  `Docs/Specs/01-CORE.md` updated.
- **First-run buffers show the new formatting** (`828ed02`). `DefaultBuffers.cs`
  puts the hotkeys and the calc trigger in code spans, names bold, italic and
  strikethrough on their own line, and closes the tour with a rule. Existing
  installs keep their content.

## Internal

- `2e3bff3` Click/caret coordinate probe. `Components/EditorPointerProbe.cs` and
  `build/src/clickProbe.js` log each editor press on both sides of the bridge, host
  DIPs against page `clientY` plus where the caret was actually drawn, to pin the
  old laptop's "caret lands one line above the click" report on either the WebView2
  input path or CodeMirror. Content-free by construction. Investigation
  `Docs/Investigations/07-EDITOR-CLICK-CARET-LINE-OFFSET.md`; still open, awaiting a
  capture.
- `720c016` `dotnet test` works again. A repo-root `global.json` selects the
  Microsoft.Testing.Platform runner; without it the .NET 10 SDK routes through
  VSTest and xUnit v3 refuses to run. The file must not be deleted. Error text, the
  two non-fixes, and the direct-exe fallback are in `Docs/Wiki/08-TEST-RUNNER-MTP.md`.
- `f3ccded` Dependency bumps: Windows App SDK to 2.4.0, xunit.v3 to 4.0.0, plus
  patch releases of the SDK build tools, test SDK, and Svg.Skia. No behaviour change.
